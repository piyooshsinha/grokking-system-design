# Learning paths

> Four paths help you choose the right amount of study for your starting point and deadline.

Every path uses [SCOPE](../guides/scope-method.md): Specify the promise, Calculate the workload, Outline the simplest flow, Probe failure, and Evolve only when a constraint requires it. The paths differ in how much time they spend learning versus practicing.

| Path | Best for | Time | Main outcome |
|---|---|---:|---|
| [One-week triage](1-week-plan.md) | An interview is close | 7 days, 2–3 hours/day | A repeatable structure and several timed rehearsals |
| [Two-week sprint](2-week-plan.md) | A short preparation window | 14 days, 1–2 hours/day | Core patterns applied to complete designs |
| [Six-week foundation](6-week-plan.md) | Building durable understanding | 6 weeks, about 1 hour/day | Breadth, deliberate practice, and failure analysis |
| [Senior and staff refresher](senior-staff-refresher.md) | Experienced, but out of practice | 6–10 hours | A focused plan based on a self-diagnosis |

## Pick by your current bottleneck

- If you cannot explain the vocabulary, take the six-week foundation and start with [fundamentals](../fundamentals/).
- If you know the concepts but struggle to apply them, use the two-week sprint and attempt each question before reading its walkthrough.
- If the interview is days away, use one-week triage. Practice and feedback matter more than adding new topics now.
- If you have done this before, record one unfamiliar design first. Use the refresher to target what the recording reveals.

## A practice loop for every path

1. Set a timer and attempt the problem from a blank page.
2. Use SCOPE to explain each decision and assumption aloud.
3. Compare your design with the repository walkthrough; mark one useful difference and one missing failure case.
4. Redo the weakest section without looking at the page.

Reading gives you examples. Retrieval, explanation, and revision show whether you can use them.
